### Data generation utilities for tacular

This directory contains scripts that convert source data (JSON / OBO / other
input files) into the autogenerated `data.py` modules used by the `tacular`
package. Only terms which have at least one valid formula/composition or mono/avg
mass are included. This package is not meant to be a replacement for OBO files, but
is instead meant to offer quick lookup of relevant terms for use in calculating
mass/composition of peptides or fragment ions.

### Where the parsing logic actually lives

The OBO/formula parsing logic is **not** in this directory — it lives in the
shipped package at `src/tacular/_datagen/` (one module per ontology, e.g.
`unimod.py`, `xlmod.py`, plus shared helpers in `_utils.py`). This is the single
source of truth, used by both:
- the `gen_*.py` scripts here (which import `build()` from `tacular._datagen.<name>`
  and only handle rendering the parsed entries into a `data.py` file), and
- the `tacular update` CLI (`src/tacular/update.py`), which regenerates data at
  runtime from freshly-downloaded OBOs into a per-user cache — see the main
  README's "Updating data from the latest ontologies" section.

If you need to fix a parsing bug, fix it in `src/tacular/_datagen/<name>.py`, not
in `data_gen/generator/gen_<name>.py` — the generator script will pick up the fix
automatically. After changing a `_datagen` module, regenerate via the recipes
below and confirm `git diff` on the resulting `data.py` is either empty (no
behavior change) or exactly the fix you intended.

### Known data-quality issues in the source ontologies

These are pre-existing quirks in the upstream ontologies, not bugs in tacular's
parsing — verified by cross-checking the source `.obo` files directly:
- **PSI-MOD** has some terms whose composition and reported mass disagree
  (`DiffFormula` sums to a different value than `DiffMono`/`DiffAvg`). A GitHub
  issue was opened upstream for this.
- **XLMOD** has ~25 entries (mostly deuterated/derivative crosslinkers) with the
  same kind of formula-vs-mass disagreement in the source file.
- **RESID** terms sometimes map to multiple different PSI-MOD entries. This
  happens when a RESID id refers to a modification type whose mass depends on
  the residue it's attached to. Since a single RESID id can't resolve to one
  mass unambiguously, `tacular._datagen.resid.build()` drops every entry whose
  RESID id occurs more than once (see `tests/test_datagen_builders_edge_cases.py`).
- **GNOme** is enormous (~200k terms), and most don't carry a resolvable
  mass/formula — many just embed a molecular weight in the free-text
  description instead of a structured composition. Only entries with a
  Byonic-style composition property (`GNO:00000202`) are included.
- **UNIMOD** entries with isotope-labelled atoms (`13C`, `15N`, ...) previously
  had those atoms silently dropped from `composition`/`formula` while the mass
  stayed correct — this was a bug in tacular's own parser (fixed; see
  `HISTORY.md`), not an upstream data issue. UNIMOD's own source data is
  otherwise clean.

### Quick overview
- Generators: individual scripts named `gen_*.py` render specific outputs
	(monosaccharides, unimod, psimod, amino acids, fragment ions, proteases,
	reference molecules, neutral deltas, etc.) by calling into `tacular._datagen`.
- Convenience: a `justfile` is provided (`data_gen/justfile`) with recipes to
	run individual generators or the full generation flow from the repo root.

Logs
- Each generator writes its own log to `data_gen/logs/<generator_name>.log`
	(e.g. `data_gen/logs/gen_unimod.log`) via `data_gen/generator/logging_utils.py`,
	in addition to printing to stderr.

How to run
- Run the full generation (recommended) from the repo root:

```bash
just -f data_gen/justfile gen
```

- Run a single generator (examples):

```bash
just -f data_gen/justfile gen-ref      # reference molecules
just -f data_gen/justfile gen-uni      # unimod
just -f data_gen/justfile gen-mono     # monosaccharides
```

Where outputs go
- Output target paths are centralized in `data_gen/constants.py` as the
	`OutputFile` enum; generators write their generated `data.py` files to those
	paths inside `src/tacular/...`.
